# 말씀 블록 – 설계 문서

작성일: 2026-11-11 · 상태: 검토 대기

## 1. 목적

- 놀이터의 두 번째 게임. 대상은 소년부 아이들 40~50명이며, 퍼즐(CODE:Block)과 같은 방식으로 함께 진행한다.
- 성경 구절(암송 구절)을 단어 블록으로 나누어 그룹 멤버들에게 나눠 주고, **서로 이야기해야만** 문장을 완성할 수 있게 한다.
- 성공 기준
  - 처음 보는 아이도 설명 없이 진행할 수 있다(입장 흐름이 퍼즐과 같음).
  - 선생님은 교실 화면 하나로 구절 준비, 진행, 힌트, 결과를 모두 다룰 수 있다.
  - 50명이 동시에 접속해도 퍼즐과 같은 수준(응답 수 ms, 끊김 없음)을 유지한다.

## 2. 사용자 확정 사항 / 가정

| 구분 | 내용 |
|---|---|
| 확정 | 정답 확인 방식은 두 가지 모두 지원하고, 관리자가 라운드마다 고른다 (A. 칸마다 바로 확인 / B. 다 채우고 제출) |
| 가정 | 입장 흐름은 퍼즐과 동일: QR → 입장 코드 → 이름 + 비밀번호 4자리 → 그룹 선택 → 수락 |
| 가정 | 관리자 권한, 방 생성, QR 크게 보기, 그룹 이름 변경, 그룹 이동·내보내기, 비밀번호 재입장은 퍼즐과 동일 |
| 가정 | 디자인은 퍼즐과 같은 CODE:Block 테마(theme.css)를 쓴다 |

## 3. 게임 흐름

### 관리자
1. 관리자 비밀번호로 로그인하고 **방 만들기** (말씀 블록 전용 방, 4자리 코드 + QR).
2. **구절 목록**에 구절을 추가한다: 본문 + 참조(예: 열왕기하 5:3).
   - 블록은 띄어쓰기 기준으로 자동으로 나뉜다. 본문에 `/`가 있으면 `/` 기준으로 나뉜다.
     (예: `말 한마디가 / 누군가의 인생을 / 바꿀 수 있어요` → 블록 3개)
   - 미리보기로 나뉜 블록을 확인할 수 있다. 블록은 최대 30개.
   - 구절 목록은 그 방에 임시로 보관되어(퍼즐의 '올린 사진'과 같음) 여러 라운드에 다시 쓸 수 있다.
3. 이번 라운드에 쓸 **구절**과 **확인 방식(A/B)**을 고르고, 그룹 수와 그룹 이름을 정한 뒤 **게임 시작**.
4. 게임 중에는 그룹별 문장 줄이 실시간으로 채워지는 모습을 본다. 블록이 고정되거나 그룹이 완성되면 띠링 소리가 나고, 완성 순서대로 순위가 매겨진다.
5. 힌트 버튼(모두 켜기/끄기 가능, 전체 그룹에 적용)
   - **참조 보여주기**: 플레이어 화면에 "열왕기하 5:3" 표시
   - **첫 글자 보여주기**: 빈칸마다 그 블록의 첫 글자 표시
   - **구절 크게 보기**: 관리자 화면(교실 화면)에만 구절 전체를 크게 띄움
6. 라운드가 끝나면 **완성 구절 크게 보기**로 다 같이 읽고, **다음 라운드 준비**를 누른다. 대기실로 돌아가며 플레이어와 그룹은 그대로 유지된다.

### 플레이어
1. 입장은 퍼즐과 같다. 게임 이름은 "말씀 블록"으로 표시한다.
2. 시작하면 그룹마다 같은 구절의 블록이 섞여서 멤버들에게 고르게 나뉜다. 블록 수보다 멤버가 많으면 블록이 없는 멤버도 생기는데, 이 멤버는 '응원·도우미' 안내를 받는다.
3. 화면 위쪽에는 **문장 줄**(번호 붙은 빈칸들)이, 아래쪽에는 **내 블록**이 있다.
   - 내 블록을 **누른 뒤 빈칸을 누르거나**, 빈칸으로 **끌어다 놓으면** 들어간다.
   - 칸에 넣은 블록은 같은 그룹 친구 화면에 넣은 사람의 색과 이름으로 바로 보인다.
   - 내가 넣은 블록을 다시 누르면 내 블록으로 돌아온다. 다른 친구 블록이 있는 칸에는 넣을 수 없다.
4. 확인 방식
   - **A. 칸마다 바로 확인**: 맞는 칸에 넣으면 그 블록이 초록색으로 **고정**된다. 틀린 칸이면 넣은 채로 남지만 고정되지 않는다(따로 안내 문구는 띄우지 않는다). 모든 칸이 고정되면 완성.
   - **B. 다 채우고 제출**: 모든 칸이 차면 그룹 누구나 **제출**을 누를 수 있다. 틀리면 그룹 전체에 "N개가 틀렸어요"만 알려 주고(어느 칸인지는 알려 주지 않음), 5초 동안 다시 제출할 수 없다. 모두 맞으면 완성.
   - 같은 글자의 블록이 두 개 이상이면(예: 같은 단어가 두 번 나옴) 서로 바꿔 넣어도 정답으로 인정한다.
5. 그룹이 완성되면 축하 화면에 완성된 구절, 참조, 순위가 나온다.

## 4. 구조

퍼즐은 4일 뒤 실제 행사에서 쓰이므로 **퍼즐 코드는 건드리지 않고** 별도 게임으로 추가한다.

```
games/verse/server.js       말씀 블록 서버 (Socket.IO 네임스페이스 /verse)
public/verse/index.html     플레이어 화면 (player.js, player.css)
public/verse/admin.html     관리자 화면 (admin.js, admin.css)
public/puzzle/theme.css     공통 디자인 (그대로 재사용)
public/puzzle/core.js       공통 도구: 소리, 토스트, 저장 등 (그대로 재사용, 퍼즐 조각 전용 함수는 쓰지 않음)
test/verse-sim.js           말씀 블록 시나리오 테스트
test/verse-load.js          말씀 블록 부하 테스트
```

- 방·관리자·플레이어·그룹·재입장·접속 표시 로직은 퍼즐 서버의 구조를 그대로 따른다(복사 후 말씀 블록용으로 수정). 공통 모듈로 합치는 정리는 행사 이후에 따로 한다.
- 서버 등록: `server.js`에 `registerVerse(io.of('/verse'))` 한 줄 추가. QR API는 `game=verse`로 그대로 쓴다.
- 허브(`public/index.html`)의 '준비 중' 카드를 말씀 블록 카드(플레이어 입장 / 관리자)로 바꾼다.

### 데이터 (서버 메모리)
- `room.verses`: `[{ id, text, ref, blocks: [문자열] }]` (최대 20개)
- `room.round`: `{ verseId, mode: 'instant' | 'submit' }`
- 그룹별: `blocks: [{ id, text, owner, slot: null|번호, locked }]`, `finishedAt`, `rank`, `lastWrong`(B 방식에서 틀린 개수), `cooldownUntil`
- 정답 판정: 칸 `i`의 정답 글자는 `verse.blocks[i]`. 블록 글자가 그 칸의 정답 글자와 같으면 정답(같은 글자 블록은 서로 바꿔도 됨).

### 실시간 전송 (퍼즐 최적화 방식 그대로)
- 블록이 움직이면 바뀐 블록 하나만, 그 그룹 플레이어와 관리자에게만 보낸다.
- 전체 상태는 참가, 그룹 선택, 시작, 완성 때만 보내고, 플레이어에게는 자기 그룹 데이터만 담는다.
- 접속/끊김은 가벼운 presence 이벤트로만 알린다.

### 오류·예외 처리
- 남의 블록 이동, 이미 찬 칸에 넣기, 게임 중이 아닐 때의 조작은 서버에서 거부한다.
- B 방식: 빈칸이 있거나 쿨다운 중이면 제출을 거부한다.
- 게임 도중 내보낸 플레이어의 블록 가운데 칸에 들어가지 않은 것은 그룹 안 다른 멤버에게 다시 나눠 준다. 칸에 들어간 블록은 칸에 그대로 둔다.

## 5. 테스트 / 검증
- 시나리오 테스트: 관리자 권한, 구절 추가와 블록 나누기(띄어쓰기, `/`), A 방식 고정, B 방식 제출(틀린 개수, 쿨다운), 같은 글자 블록 바꿔 넣기, 남의 블록·찬 칸 거부, 재입장, 내보내기 재분배, 그룹 데이터 분리, 순위, 다음 라운드.
- 부하 테스트: 50명·8그룹, CPU 0.1코어 제한에서 응답 지연과 전송량 측정.
- 브라우저 테스트: 관리자 1명 + 휴대폰 2명이 실제로 누르기/끌기로 A·B 방식을 각각 끝까지 진행.

## 6. 이번 범위에서 제외
- 라운드 누적 점수판, 타이머 제한, 음성 읽기.
- 퍼즐과 공통 코드 합치기(행사 이후 정리).
